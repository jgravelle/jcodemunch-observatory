# jcodemunch observatory

Public OSS code-health observatory. Weekly snapshots of complexity,
dead code, dependency cycles, coupling, test gaps, and churn surface
across a curated set of open-source repositories — generated by
[jcodemunch-mcp](https://github.com/jgravelle/jcodemunch-mcp).

**Live site:** https://jgravelle.github.io/jcodemunch-observatory/
(or your custom domain — see "Custom domain" below)

## What this is

Every Monday at 06:00 UTC, a GitHub Action clones each repo in
`observatory.config.json`, indexes it with jcodemunch, runs
`get_repo_health`, and publishes a static site with:

- Six-axis health radar per repo (complexity, dead_code, cycles,
  coupling, test_gap, churn_surface)
- Per-repo history (capped at 52 weeks)
- JSON + RSS feeds for programmatic consumption

The pipeline is deterministic and the output is hosting-agnostic; we
publish to GitHub Pages but the same artifacts work behind Caddy,
nginx, fly.io, S3, etc.

## Repository list

Edit `observatory.config.json` to add or remove repos. Each entry
takes:

```json
{
  "url": "https://github.com/owner/repo",
  "label": "Display Name",
  "branch": "main",
  "languages": ["python"],
  "blurb": "One-line description shown on the landing page."
}
```

`branch` and `languages` are optional. `label` defaults to
`<owner>/<repo>` when omitted.

## Manual run

```bash
gh workflow run observatory.yml
```

Or locally:

```bash
pip install jcodemunch-mcp
jcodemunch-mcp observatory build \
  --config observatory.config.json \
  --output-dir public
```

## Custom domain

1. Add a `CNAME` file at the repo root with your domain
   (e.g. `report.jcodemunch.com`).
2. Add a `CNAME` DNS record at your registrar pointing the subdomain
   to `jgravelle.github.io`.
3. In repo Settings → Pages, set the custom domain and enable
   "Enforce HTTPS" once the cert provisions.

## Methodology

See the [`get_repo_health` documentation](https://github.com/jgravelle/jcodemunch-mcp#get_repo_health)
for the scoring methodology. Each axis is a 0-100 score; lower is
healthier. The radar combines all six into one shape — the smaller
the polygon, the healthier the repo.

History is capped at 52 entries per repo to keep the output small;
each weekly run prepends a fresh snapshot and trims the tail.
